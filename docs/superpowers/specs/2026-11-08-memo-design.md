# 메모(검토 주석) — 설계

> 2026-11-08 · 구현 전 승인 문서. rhwp 포크(`kossa/0.8.7`)에서 작업하며 upstream 기여 가능한 형태를 유지한다.

## 1. 왜

문서를 검토할 때 본문을 고치지 않고 의견을 다는 수단이 없다. 한글의 **검토 ▸ 메모**와 같은 기능 —
본문 일부에 메모를 붙이면 오른쪽 여백에 풍선(작성자·시각·내용)이 뜨고 안내선으로 이어지는 것 — 을 넣는다.

엔진은 **HWPX** 메모를 이미 읽고 쓴다(`fieldBegin type="MEMO"` → `Field{field_type: Memo, memo_paragraphs, memo_index, command "MEMO/…"}` → HWPX 재직렬화).
**HWP5(.hwp)** 는 메모 본문을 **쓰기만** 한다 — 파서는 `memo_index`만 읽고 `HWPTAG_MEMO_LIST` 꼬리를 건너뛰어(`parser/control.rs`, `parser/body_text.rs`) 본문·시각이 비고,
한글이 만든 .hwp 메모는 `FieldType::Unknown` + command `MEMO/…`로 들어온다(#5866). 없는 것은 **표시 · 편집 명령 · UI**, 그리고 **.hwp 메모 본문 읽기**다(범위는 §2.1).

## 2. 목표 · 비목표 · 금지

**목표**
- 검토 리본에 메모 그룹: **메모 넣기 · 메모 지우기 · 이전 · 다음 · 메모 표시 · 메모 안내선 · 메모 내용 보기** (한글 2024 배치를 따른다).
- 선택 영역(없으면 캐럿 위치의 낱말)에 메모를 단다. 오른쪽 여백 풍선에 **작성자 · 작성 시각 · 내용**. 풍선 안에서 바로 내용을 고친다.
- 작성자 = **도구 ▸ 환경 설정 ▸ 사용자 이름**(새 항목). 비어 있으면 메모를 처음 넣을 때 환경 설정으로 안내한다.
- 한글 2024가 만든 메모를 똑같이 보여 주고, rhwp가 만든 메모를 한글 2024가 열고 보여 준다(파라미터 7종을 한글 실측과 같게 쓴다).
- 저장(HWPX·HWP) 뒤 다시 열어도 메모가 그대로다. 실행 취소/다시 실행에 메모 넣기·지우기·내용 고치기가 들어간다.

### 2.1 .hwp(HWP5) 범위 (사용자 결정 2026-11-08: HWPX 먼저, .hwp는 보호만)
- 메모 기능은 **HWPX에서 완전히** 동작한다(읽기·표시·넣기·고치기·지우기·저장).
- .hwp를 열면 메모는 **앵커 위치·작성자만** 표시한다(내용 없음 — 풍선에 "내용은 .hwp에서 읽지 못합니다" 회색 안내). .hwp에서 새 메모 넣기는 된다(HWPX로 저장하면 보존).
- 메모가 든 문서를 **.hwp로 저장**하려 하면 저장 전에 경고: "이 문서의 메모 N개 중 내용을 읽지 못한 것이 있어 .hwp로 저장하면 메모 내용이 사라집니다. HWPX로 저장하세요." [HWPX로 저장] [그래도 .hwp로] — 읽은 내용이 있는 메모는 기존 `MEMO_LIST` 쓰기로 보존된다.
- HWP5 `MEMO_LIST` 파서(내용·시각 읽기)는 **후속 과제**로 남긴다.

**비목표**
- .hwp 메모 본문 읽기(§2.1).
- 메모 답글(스레드), 메모 해결/완료 표시, 변경 내용 추적(교정부호).
- 메모 모양(색 5종) 바꾸기 — 이번엔 기본 모양 하나. 파일에 든 다른 모양은 **보존**만 한다.
- 메모 안 서식(굵게·표 등) — 내용은 일반 문단 텍스트. 파일에 든 서식 있는 메모는 보존하고 텍스트만 보여 준다.
- 인쇄 시 메모 출력.

**금지**
- 메모가 있는 문서를 열고 저장했을 때 메모가 사라지거나 한글이 파일을 못 여는 것(과거 #5866 — 빈 subList 없으면 한글이 열기 실패).
- 메모 표시를 켜도 본문 조판(줄바꿈·쪽수)이 바뀌는 것. 풍선은 **오버레이**이고 조판에 관여하지 않는다.
- 포크 밖 사용자에게 보이는 곳에 특정 조직 이름이 들어가는 것.

## 3. 사용자가 보는 모습

### 3.1 넣기
1. 본문을 긁어 선택하고 **검토 ▸ 메모 넣기**(단축키 Ctrl+N,C 는 한글과 같다 — 기존 단축키와 충돌하면 빌더가 조정). 선택이 없으면 캐럿이 놓인 낱말이 대상.
2. 오른쪽 여백에 노란 풍선이 생기며 **커서가 풍선 안으로** 들어간다. 머리글: `사용자 이름 · 2026/11/08 23:18`. 바로 타이핑한다.
3. 본문의 대상 구간은 연한 색 밑줄(한글은 연한 배경)로 표시되고, 풍선과 **안내선**으로 이어진다.
4. Esc 또는 본문 클릭 → 본문으로 돌아온다. 내용이 비어 있어도 메모는 남는다(한글과 같다).

### 3.2 보기
- **메모 표시** 켜짐(기본, 문서에 메모가 하나라도 있으면): 쪽 오른쪽에 여백 띠가 생기고 풍선이 쪽 세로 순서대로 쌓인다. 겹치면 아래로 민다(한글과 같은 단순 적층).
- **메모 안내선** 끄기: 풍선은 남고 선만 사라진다.
- **메모 내용 보기**: 아래쪽에 목록 창 — 쪽 · 작성자 · 시각 · 내용 첫 줄. 항목 클릭 → 그 메모로 이동.
- 풍선 클릭 → 본문 대상 구간이 선택되고 풍선이 활성(진한 테두리). 본문 대상 구간 클릭 → 해당 풍선 활성.
- **이전 · 다음**: 문서 순서로 이동(활성 풍선 기준, 없으면 캐럿 기준).

### 3.3 지우기 · 고치기
- 활성 풍선에서 **메모 지우기**, 풍선 머리의 ✕, 또는 풍선 안에서 내용을 다 지운 뒤 Backspace 한 번 더 → 메모 삭제(확인 없음, 실행 취소 가능). 본문 텍스트는 남는다.
- 풍선 안 편집은 일반 textarea. 포커스가 빠질 때 한 번에 엔진에 반영(실행 취소 1단계).
- 대상 구간 텍스트를 사용자가 전부 지우면 메모도 함께 지운다(필드 범위가 사라지므로). 지워지기 전에 상태줄로 한 줄 알린다.

### 3.4 환경 설정
- **도구 ▸ 환경 설정 ▸ 일반**에 `사용자 이름` 입력란(브라우저 저장, 기기별). 메모 작성자와 (후속) 문서 요약 작성자에 쓴다.

## 4. 어떻게 — 결정 사항

### 4.1 엔진(Rust, `wasm_api.rs` + `document_core/commands/memo_ops.rs` 신설)
| API | 하는 일 |
|---|---|
| `insertMemo(author, text, createdAt)` | 현재 선택(없으면 캐럿 낱말)에 `Field{Memo}` 범위를 만든다. `memo_index` = 문서 최댓값+1. 형상은 **한글 2024 실측(`samples/hwpx/aift.hwpx` section2의 MEMO 2건)을 그대로 따른다**: `command` = `MEMO/65535/<index>/<메모별 난수>/<문서 공통값>/<author>/\;;` (memoPr이 있어도 `MemoShapeIDRef=65535`), `parameters` 7종(Prop, Command, ID=`memo<index>`, Number, Author, **CreateDateTime** = ISO 8601 UTC `2026-04-14T21:36:44Z`, MemoShapeIDRef), `fieldid`는 문서의 메모가 공유, `memo_paragraphs` = 텍스트 한 문단(빈 텍스트도 문단 1개 필수). 반환 `{ok, fieldId}` |
| `setMemoText(fieldId, text)` | 본문 문단의 텍스트만 바꾼다(첫 문단 run 교체, 나머지 문단 유지하지 않음 — 이번엔 단순 텍스트) |
| `removeMemo(fieldId)` | 필드 범위 제거, 본문 텍스트 유지 (`removeFieldAt` 계열 재사용 가능하면 재사용) |
| `getMemoList()` | JSON 배열: `{fieldId, index, author, createdAt, text, page, anchorRects[{page,x,y,w,h}], location(본문/셀/머리말…)}` — 앵커 사각형은 `getSelectionRects` 계열과 같은 좌표계(HWPUNIT, 쪽 기준) |
| `getMemoAtCursor()` | 캐럿이 메모 범위 안이면 fieldId |

- 셀 안·머리말·각주 안의 메모는 **읽기·표시**는 하되, 이번 **넣기는 본문과 표 셀**까지만.
- **memoShape**: header에 `memoPr`을 **추가하지 않는다** — 사용자 제공 실측 파일(한글 13.0.0.2353, 2026-11-08)은 memoPr 없이 `MemoShapeIDRef=65535`만으로 메모를 저장하고 한글이 정상으로 연다. 화면 풍선 색은 한글 기본값(채움 `#CBFF99`, 활성 `#FDBCDD`, 선 `#A9A9A9`, 폭 15591 HWPUNIT)을 **스튜디오 상수**로 쓴다. 문서에 memoPr이 있고 필드가 그것을 가리키면 그 색을 쓴다.
- **`fieldid`**: 한글은 MEMO 필드에 상수 `623209829`를 쓴다(aift.hwpx, 사용자 파일, 파서 시험 모두 동일). 새 메모도 이 값을 쓴다. `id`(fieldBegin)는 문서 내 고유 난수, command 토큰 3은 메모별 난수, 토큰 4는 문서 공통 난수(첫 메모 때 만들어 이후 재사용).
- 메모 subList 문단의 `paraPrIDRef/styleIDRef/charPrIDRef`는 앵커 문단의 값을 따른다(한글 실측: 본문과 같은 스타일 id).
- **선택 범위 제약 (설계자 결정)**: 1차는 기존 범위 필드 경로(하이퍼링크 삽입과 같은 **한 문단 안**)를 따른다.
  - 선택이 문단을 넘으면 **첫 문단의 선택 구간에만** 달고 상태줄에 "메모는 첫 문단에 달렸습니다"를 띄운다.
  - 선택이 하이퍼링크·누름틀 등 기존 필드와 겹치면 **거부**하고 상태줄 안내("링크/누름틀 안에는 메모를 달 수 없습니다 — 바깥을 선택하세요").
  - 다단락·중첩 필드는 후속(엔진 편집 경로 `text_editing.rs`의 범위 유지가 같은 문단 짝만 다룬다).
- 모든 변경은 기존 스냅샷 명령 경로(`executeOperation({kind:'snapshot'})`)로 실행 취소에 들어간다. 엔진 단위 시험: 넣기→직렬화 HWPX→재파싱 동일, HWP5 왕복 보존, 지우기 후 본문 텍스트 보존, 선택 없을 때 낱말 범위.

### 4.2 스튜디오(TS)
- `src/memo/`: `memo-model.ts`(목록 캐시·활성 상태), `memo-layer.ts`(오버레이: 여백 띠·풍선·안내선·본문 밑줄; `SelectionRenderer`처럼 `VirtualScroll` 위 레이어), `memo-pane.ts`(내용 보기 목록), `memo-settings.ts`(표시/안내선/내용보기 상태 — `userSettings.view`에 저장).
- 레이아웃 (설계자 결정 — §3.2와 통일): 메모 표시가 켜지고 메모가 있으면 **쪽마다 오른쪽에 여백 띠**를 붙인다(한글과 같다). 띠 폭은 memoPr `width`(15591 HWPUNIT ≈ 55mm)에 줌을 적용한 값. 여러 쪽을 가로로 배열하는 모드(`page-arrangement.ts`)에서는 각 쪽이 자기 띠를 가지므로 왼쪽 쪽의 메모는 그 쪽 바로 오른쪽(다음 쪽 앞)에 놓인다. **폭 맞춤 줌은 띠를 포함한 폭**으로 계산한다. `VirtualScroll`의 쪽별 폭에 띠를 더하는 방식이며, 쪽 자체 크기·조판은 불변.
- 재계산 시점: 문서 변경 이벤트(기존 `eventBus` 의 레이아웃/페이지 갱신 이벤트) 뒤 `getMemoList()` 한 번. 10쪽 이상 문서에서도 즉시성 유지 — 앵커 사각형은 보이는 쪽만 그린다.
- 명령: `review:memo-insert`, `review:memo-delete`, `review:memo-prev`, `review:memo-next`, `review:memo-show`(토글), `review:memo-guide`(토글), `review:memo-list`(토글). 리본 `review` 그룹 + 검토 세로 메뉴. `canExecute`는 문서 열림/메모 존재/활성 메모 유무로.
- 환경 설정 대화상자(`options-dialog.ts`) 일반 탭에 사용자 이름. `userSettings.general.userName`.
- i18n ko/en. 시험: 명령 활성 조건, 풍선 적층 계산(순수 함수), 설정 저장, `getMemoList` 목 데이터로 레이어 DOM 생성.

### 4.3 한글 호환 검증
- rhwp로 메모 3개(본문·표 셀·빈 내용)를 넣어 HWPX·HWP로 저장 → **한글 2024에서 열어** 풍선·작성자·시각이 보이는지 확인(사용자 PC). 실패 시 파라미터·memoPr을 실측과 맞춘다.
- 한글이 만든 메모 파일을 rhwp로 열어 → 저장 → 한글 재열기 동일.

## 5. 빌더에게 맡기는 것
- 풍선·밑줄·안내선의 색·두께·글꼴(스튜디오 테마 토큰 사용, 다크 모드 포함).
- 적층 알고리즘 세부, 여백 띠 폭 상수, 접근성(풍선 textarea 레이블).
- 단축키 최종 결정(충돌 시).
- `removeFieldAt` 재사용 여부 등 내부 구현 선택.
- 메모 내용 보기 창의 위치(아래 패널 vs 오른쪽 패널).

## 6. 실측 기준 파일
- 한글 2024가 저장한 메모 HWPX는 리포에 이미 있다 — **`samples/hwpx/aift.hwpx`** section2에 MEMO 2건(빌더 검토에서 확인). `parameters`·`CreateDateTime` 값은 §4.1에 옮겨 적었다. 엔진·스튜디오 시험의 기준 파일로 쓴다.
- 두 번째 기준: 사용자가 준 한글 13.0.0.2353 저장본(표 셀 안 메모 1건, memoPr 없음) — **`local-samples/memo-hangul13-table-cell.hwpx`**, `.gitignore` 대상(내부 문서라 커밋 금지). 셀 안 메모 표시·셀 안 넣기 수동 검증에 쓴다.

## 7. 작업 순서(제안)
1. 엔진 API 4종 + 단위 시험 → wasm 빌드
2. 스튜디오 오버레이(표시만) → 한글 메모 파일로 확인
3. 넣기·고치기·지우기 + 실행 취소 + 리본·메뉴·환경 설정
4. 내용 보기 창, 이전/다음
5. 빌드·설치 → 한글 호환 검증(사용자) → 배포는 사용자 확인 후
